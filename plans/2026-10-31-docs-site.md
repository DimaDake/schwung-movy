# Movy website + manual rework (2026-10-31)

**Goal.** Replace the 2,500-line `MANUAL.md` with a multi-page user site on
GitHub Pages (MkDocs Material) that reads like a real instrument manual
(Elektron / Move / Deluge / TE): how to use Movy and what it is good for
musically. No design rationale, no internals, no timing numbers, no history.
The site also answers "how do I install it" — Schwung first, then Movy.

## Layout

- `mkdocs.yml` (repo root), `site/` = docs_dir, published by
  `.github/workflows/pages.yml` to `https://dimadake.github.io/schwung-movy/`.
- `site/index.md` home · `site/install.md` · `site/manual/*.md` (one chapter
  per page) · `site/reference/*.md` (controls, troubleshooting).
- `site/assets/screens/` — 4× upscaled test baselines (stay in sync with the UI).
- `site/assets/diagrams/` — SVGs generated from code: the Move panel with LED
  states and callouts, pad layouts (from `src/keyboard/layouts.ts`), step-row
  maps, signal flow. Track colours come from `src/seq/colors.ts`.
- `scripts/site/build-assets.mjs` regenerates both; it only exports screens that
  a page references, and fails on a reference to a missing baseline.
- `scripts/install-movy.sh` — one-line install over Schwung Manager's own
  install endpoint (keeps the manager's boot-target registration).

## Rules for the content

1. Task first: what you do, which buttons, what you see (screenshot/diagram).
2. One "Musical uses" note per feature only where the use is real and obvious.
3. Controls reference is the only exhaustive table set.
4. `MANUAL.md` becomes a pointer; README becomes a short landing page with
   current (static) screenshots, no animated montage.
